# 波段助手买点监控 — 上下文固化

> 本文件固化 2026-11-24 会话中已确认的需求、决策与调研结论，供后续在 stock 项目里继续实施时直接接续。配套实施计划见 `PLAN.md`。

## 一、需求起源

监控同花顺 Mac 客户端内置的「波段助手」指标（K 线主图上的绿色 **B** 买点 / 红色 **S** 卖点标注），当指定标的出现 **60 分钟买点**时，自动向**企业微信**发送通知消息。

## 二、指标原理（用户提供的官方说明原文）

> (1) 定义原理：波段助手是根据近 7 日收盘移动平均值及近 13 日收盘移动平均值，乘一定系数后上穿形成金叉和下穿形成死叉判断买卖点。根据 K 线开盘收盘价及换手率判断持有还是观望。该指标多用于波段操作，帮助用户波段做 T，低位买入，高点卖出。
>
> (2) 应用法则：a. 买点：买字买入，黄色荧光柱表示持有。b. 卖点：卖字卖出，蓝色荧光柱表示观望。

## 三、关键瓶颈（决定方案形态）

**该指标的 MA7 / MA13 乘数（系数）官方从未公开。** 联网调研只找到内容相同的求助帖（理想股票论坛 55188），无源码；同花顺指标平台上同名的另一个「波段助手」是 RSI + 黑码线体系，与本指标无关。

因此无法做到与同花顺那个 B/S 点完全一致，只能做「**行为等效、系数可调、尽量贴近截图**」的复刻。系数需用户用同花顺截图对照微调。

## 四、四项已拍板决定

1. **系数**：做成可调参数 + 合理默认值（K1 = K2 = 1.00 起步，退化为标准 MA7/MA13 金叉），后续截图对照微调。
2. **周期**：60 分钟与日线**两个都算、分别推送**，且**彻底分离**——60 分钟轮次只取 m60 行情，日线轮次只取 daily 行情，互不代取（原「日线二次确认标签」已于 2026-11-26 删除）。
3. **标的**：多只自选股，从配置文件读取（代码清单由用户提供，不硬编码）。
4. **推送**：企业微信群机器人 webhook（markdown 消息）。

## 五、已验证的调研结论（可直接采用）

### 行情数据
- `akshare.stock_zh_a_hist_min_em(symbol="300750", period="60", adjust="qfq")`：60 分钟 K 线**含换手率（%）**，列名 `时间,开盘,收盘,最高,最低,涨跌幅,涨跌额,成交量,成交额,振幅,换手率`。1 分钟周期才不含换手率，不影响本方案。
- 日线 `akshare.stock_zh_a_hist(symbol, period="daily", adjust="qfq")`：同样含换手率。
- 备选：东财 push2his 裸接口（同源，`fqt=1` 前复权，`fields2` 含换手率，须带 Referer/User-Agent）。
- baostock 分钟线不含换手率，不适合。
- akshare 本质是爬虫封装：须锁版本、做列名适配层、串行请求 + 小延迟、指数退避重试（1s→3s→8s）、失败告警与日志。东财限频社区实测约 45–60 次/分钟（推测值）。

### 60 分钟收线时点与防假信号
- A 股每天 4 根 60 分钟 K 线，收线时刻：**10:30 / 11:30 / 14:00 / 15:00**。
- 调度延迟到收线后 1–3 分钟：**10:33 / 11:33 / 14:03 / 15:05 / 15:10** 只跑 60 分钟；日线买卖点独立在**每个交易日 18:30** 跑一轮。
- **闭合校验**：最后一根 K 线时间标签必须 ∈ {10:30,11:30,14:00,15:00} 且成交量稳定，否则跳过或用上一根已闭合 K 线。切勿用盘中未收盘的最后一根算金叉死叉——这是假信号的主要来源。

### 推送
- 企业微信群机器人：`POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=KEY`，body `{"msgtype":"markdown","markdown":{"content":"..."}}`，返回 `errcode==0` 成功。
- markdown 内置颜色：`info` 绿 / `comment` 灰 / `warning` 红；频率上限 20 条/分钟。
- webhook key 必须存环境变量（`~/.env`），绝不硬编码、入 git 或打日志。

### 定时
- macOS 用 launchd：`~/Library/LaunchAgents/*.plist`，`StartCalendarInterval` 支持多时点数组，睡眠唤醒后会补跑，优于 cron。
- launchd 不继承 shell PATH，Python 与脚本均用绝对路径。
- WorkBuddy automation 也能执行本地脚本 + 推企微，但关机/退出客户端会中断、消耗 token，不如 launchd 稳妥。

## 六、推测待调参项（未验证，需截图对照）

- 系数默认值 K1 = K2 = 1.00，以及调参范围 0.98 ~ 1.10
- 持有/观望规则：`收盘 > 开盘 且 换手率 ≥ 阈值`（黄柱持有 / 蓝柱观望），阈值 60 分钟 1.0%、日线 2.0% 均为推测
- 日线二次确认策略、跨周期信号合并策略
- 系数方向：增大 K1 → 金叉提前/死叉滞后（偏多）；增大 K2 → 金叉滞后/死叉提前（偏空）。一次只动一个、步长 0.01。

## 七、调参对照方法

1. `backtest.py` 拉历史 K 线，导出 `time,close,ma7,ma13,fast,slow,cross_up,cross_down,hold` CSV，列出脚本复刻的 B/S 点。
2. 同花顺 Mac 打开同标的同周期截图（**统一用前复权 qfq**），对比截图 B 点时间与回测 CSV：脚本金叉偏晚 → 增大 K1 或减小 K2；偏早 → 反向。
3. 同样方法核对黄柱/蓝柱区间，调换手率阈值与 require_bullish。
4. 调好后写回 config.yaml，先 `dry_run: true` 跑 1–2 天，确认无误再开推送。

## 八、风险提示

均线金叉死叉信号本质滞后，收线后才确认；系数与持有规则为推测复刻，无法保证与同花顺一致；免费行情接口可能变更字段或限频。脚本输出仅为技术指标参考，不构成投资建议。
