## 晚 · 信号位置优化（用户要求：提前一根 + 过滤前根是卖的买点）

**改了什么**（indicator.py 新增 `postprocess_signals()`，两个参数在主流程与回测都透传）：

**重要结论：靠加大 `ma7_lead_pct` 无法实现「整体提前一根」。** lead 0→2.0，中位偏移只从 −1 走到 +1（同根率始终 7~8%），精度却从 53% 掉到 35%——提前量只让信号在 MA7 附近抖动，不能让整条序列平移，且提前触发的点大量落在震荡区变假信号。

## 晚 · 修复 git 推送失败

**仓库事实**（容易踩）：git 根目录是 `/Users/holyli/stock`，**不是** `wave-monitor/`；remote 名是 **`stock`**（不是 origin），所以命令是 `git push stock master`。

**三层原因**：
1. 本地 `master` 没设 upstream → `git push` 直接报 no upstream。
2. 远端 `master` 是 GitHub 网页建的**空 Initial commit**（`df25ea9`，不含任何文件），与本地 `6f7b55c` **无共同祖先** → 必然 non-fast-forward 被拒。已按用户确认 **force push 覆盖**。
3. 网络偶发 `LibreSSL SSL_connect: SSL_ERROR_SYSCALL` —— 重试即通，非主因。

**残留故障（已绕过）**：HTTPS 方式下每次 push 都报
`unable to unlink '~/.git-credentials.lock': Operation not permitted` + `fatal: unable to write credential store`。
根因：锁文件带 macOS `com.apple.provenance` 扩展属性，git 进程无法 unlink（shell 的 `rm -f` 可以）。
尝试过写钥匙串（`git credential-osxkeychain store`）—— 这个进程**没有钥匙串访问权限**，写入静默失败，`security find-internet-password` 查不到。

**最终解法：remote 从 HTTPS 改成 SSH**（`git@github.com:holyli/stock.git`）。`ssh -T git@github.com` 已验证通过（`Hi holyli!`），改完 push 再无误报，也彻底不碰凭据文件。用户已有 `~/.ssh/id_ed25519`。

**结论**：这台机器上凡是 GitHub 推送，优先用 SSH，别用 HTTPS + credential.helper=store。

## 晚 · 收盘强度 / 穿越幅度 / 量能 三个特征量化（21:55-22:00）

用户质疑「收盘位置不重要吗」，顺带把三个候选特征全量化了（口径：lead=0、rel=1.0、skip_buy_after_sell、shift=0，±1 同向匹配，36 个买点）。

**① 收盘强度：无效，不做。**
- 加「要求收阳」或「收盘位置 (close-low)/(high-low) ≥ 0.5/0.6/0.7/0.8」后，精度 54.0% 基本不动（个别档还降），召回一路掉到 32.8%。
- 根因：命中组收盘位置均值 0.710、未命中组 0.718；收阳比例 95% vs 94%——**两组几乎完全重合**。
- 解释：买点定义就是「收盘上穿 MA7」，这条前置条件已把弱收盘样本筛掉，特征被吃掉了，没有增量信息。

**② 穿越幅度：无效且冗余，不做。**
- 「收盘高出 MA7 的 %」≥0.2% 时精度 55.9%（+1.9pt，噪声内），再抬高就降。
- 与换手门组合反而更差（rel=2.0 单独 68.4% → 加穿越≥0.3% 变 66.7%）。

**③ 量能倍数：强特征，但决定不设硬门，改为标注。**
